1. 目標與決策

項目決策
與官方 API 關係 完全取代 — 不再依賴 EINVOICE_APP_ID / EINVOICE_API_KEY
產品模型 類似銀行同步：抓取 → 待審核佇列 → 勾選匯入（不自動入帳）
爬蟲技術 後端 Playwright（禁止 App 內嵌 WebView，吸取 SMB-209 教訓）
憑證儲存 手機條碼 + 查詢碼僅本機 AES-256-GCM 加密；後端 session 暫存 5 分鐘
會員限制 同步與匯入需會員資格（與銀行同步 gating 一致）

4. 前端實作

資料庫（Migration 037）

  • einvoice_sync_config — 自動同步、回看天數、預設帳戶/分類、上次同步狀態
  • einvoice_pending_invoices — 待審核佇列（pending / imported / dismissed）
  • einvoice_sync_runs — 同步執行紀錄

服務層

  • frontend/src/services/einvoice/scrape-api.js — 後端 scrape API 客戶端
  • frontend/src/services/einvoice/carrier-sync.service.js — 同步編排、去重、自動同步
  • frontend/src/core/repositories/einvoice-sync.repo.js — 本機資料存取

UI 入口

  • 設定 → 載具同步（/settings/carrier-sync）
  • 功能列表「電子發票匯入」→ 同上
  • /einvoice-import → 重新導向至載具同步頁

使用者流程

  1. 輸入手機條碼與查詢碼（可加密記住）
  2. 設定自動同步、回看天數、預設匯入帳戶/分類
  3. 點「立即同步」— 若需驗證碼則顯示對話框
  4. 在「待審核發票」勾選 → 匯入或略過

5. 去重規則

  • 已存在於 einvoice_invoice_imports → 跳過
  • 待審核佇列中 status = pending → 跳過
  • status = dismissed → 不再顯示

8. 部署檢查清單

  1. 後端設定 EINVOICE_CLIENT_SHARED_KEY；前端設定 VITE_EINVOICE_CLIENT_SHARED_KEY
  2. 生產啟用：EINVOICE_SCRAPE_USE_PLAYWRIGHT=1
  3. 伺服器安裝 Chromium：npx playwright install chromium
  4. 確認 EINVOICE_PORTAL_LOGIN_URL 指向正確的財政部查詢頁
  5. 若官方改版 DOM，更新 EINVOICE_SCRAPE_SELECTORS_JSON
  6. 建議每週執行真實爬蟲 smoke，及早發現 selector 失效
注意：開發與 CI 預設使用 mock provider，不會連線財政部真實網站。上線前務必在 staging 以真實載具驗證 Playwright 流程。

9. 風險與緩解

風險緩解
財政部改版 DOMselector 集中定義 + einvoice_portal_changed 明確失敗；可 JSON 覆寫
驗證碼 / 反爬人工輸入驗證碼；嚴格 rate limit；不做 OCR
WebView 被封僅後端 Playwright，不在 App 內爬
查詢碼傳輸HTTPS + 短期 session；server log 不記錄查詢碼
