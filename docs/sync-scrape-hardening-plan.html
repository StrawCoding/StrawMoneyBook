銀行同步 / 載具同步：爬蟲治本計畫與線上實測驗證

產出日期 2026-06-26 · 限制條件：手邊資源僅能採爬蟲方式 · 驗證方式：對財政部線上環境真實瀏覽器實測

一句話結論：之所以「修了又壞」，不是 bug 沒修乾淨，而是抓資料的方式選錯了——一直在解析「會隨官方改版而變的畫面 DOM」。在仍只用爬蟲的前提下，治本做法是改抓網頁自己呼叫的 JSON API（網路攔截），瀏覽器只留給「登入 + 圖形驗證碼」。本計畫已對官方線上環境逐項實測驗證。

一、線上驗證結果（已實測，非推測）

用真實 Chromium 連 www.einvoice.nat.gov.tw（curl 會被 WAF 擋 403，故必用瀏覽器）。以下每一條都附實測證據。

已驗證 官方站已改為 Vue/Vite SPA，資料走 JSON API。 載入時抓到 assets/index.*.js、vendor.*.js，資料來自獨立主機 service-mc.einvoice.nat.gov.tw / service-m.einvoice.nat.gov.tw，路徑樣式 /act/login/api/...、/ptl/portal/api/...。
已驗證 登入頁真實選擇器（取代現行猜測式選擇器）。 #mobile_phone（maxlength 10 / inputmode numeric）、#password（placeholder「驗證碼(密碼)」）、 #captcha、登入鈕 #submitBtn、身分分頁鈕文字「手機條碼 / 自然人憑證 / 行動自然人憑證」。
已驗證 圖形驗證碼已改成 JSON API，且必須帶 token。 GET service-mc.einvoice.nat.gov.tw/act/login/api/act002i/captcha 回 { token:"L_CAPTCHA_<uuid>", image:<base64 png> }（HTTP 200）。 下圖為本次實測「直接從該 API 抓回並解碼」的驗證碼圖，清晰可辨——證明不需要再截畫面 DOM 圖片：
已驗證 登入是 OAuth2 / SSO 流程。 攔到 /act/login/api/proxy/login → /sso/login/oauth2/auth；「手機條碼發票查詢」選單需登入後才開放（未登入點擊回首頁）。

二、根因：為何反覆「修了又壞」

現行 backend/src/einvoice/playwright-provider.js 的四個致命假設，全部與「已改版的新站」不符：

現行做法線上實況後果
查詢 URL 寫死舊站 .../portal/btc/mobile/btc502w/search新站已無此路徑（SPA）進不了查詢頁
用一長串猜測選擇器解析 table tbody tr + regexSPA 表格結構/class 隨改版變解不到發票，打地鼠
截 DOM <img> 當驗證碼、送出不帶 tokencaptcha 改 JSON API、需 token 綁定驗證碼必失敗
登入未走 OAuth2新站為 OAuth2 / SSO登入流程斷裂

歷次修復（v1.3.16 / 17 / 19 / 24、SMB-240 / 245…）都只是換選擇器，從未改變「抓資料的方式」，所以一直壞。銀行端 FirstBankAutomation.java 同屬此類（解析 table.CnbTable / 座標點擊 + OCR）。

三、治本策略（仍在爬蟲範圍內）

1 · 抓 JSON 而非 DOM

用 page.on('response') 攔截網頁自己發出的查詢 XHR，拿結構化 JSON；DOM/CSS 改版不再壞，只有官方 API 合約改變才會（罕見且可監控）。

2 · 瀏覽器只做登入

瀏覽器只負責 OAuth 登入與顯示/輸入圖形驗證碼；captcha 走 JSON API 取 {token,image}，送出時帶 token。

3 · 全面設定化

URL / 選擇器 / endpoint pattern 全走 env 可覆寫；未來官方小改版＝改設定，不必改碼、不必重新發版。

4 · 排程合約自檢

定時打登入頁 + captcha API 斷言形狀，drift 在使用者踩到前先告警——這就是終結打地鼠的機制。

七、風險與已知限制（誠實揭露）

項目說明 / 對策
載具查詢 API 確切 endpoint需「登入後」才出現（lazy chunk）；實作首跑須用測試帳號攔截一次以鎖定 pattern（攔截機制已備）。
OAuth2 風控若加裝置指紋，headless 可能被擋；必要時改 headless:false + persistent context。
銀行端需真機 / 模擬器驗證，伺服器環境無法完成。
更穩解申請官方免費 appID 走正式 API 仍最穩；惟使用者已表明資源限制只能爬蟲，故本計畫以爬蟲治本為主。
